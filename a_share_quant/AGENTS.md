# A 股量化项目长期开发规范

## 每次接手
- 先读本文件、`strategy_spec.md`、`research_log.md`、`docs/roadmap.md` 和最近报告，再检查 Git 状态与历史。保留其他项目及未提交改动。
- 当前项目是独立研究基线 `R0`，**不是**此前 V1–V4 的恢复版。未实际获得的会话、文件、数据和结果必须明确标注缺失。
- 重要策略定义、参数、算法变化及结论必须进 Git；聊天不能代替仓库记录。每项研究说明数据快照、代码提交、参数、样本范围和局限。
- 项目目录是 `a_share_quant/`。不要对同仓库 Bellworks 分支做覆盖、合并或强制推送。

## 数据与时间边界
- 禁止编造行情或结果。人工价格序列只能出现在测试中，命名为 synthetic，不能用于声称收益。
- 原始日线、因子、交易日历、证券生命周期和来源响应分开保存。记录来源 URL、获取 UTC 时间、校验和、复权方式、单位、授权状态及可用时点。
- 未确认再分发许可的行情、账户信息、密钥和供应商凭据不得提交。默认忽略 `data/raw/`、`data/processed/`、`data/vendor/`、本地环境。
- 不混用前复权、后复权、不复权。研究采用固定基准归一的累计复权价格；真实成交与涨跌停检查使用原始价格。禁止用当前复权快照冒充历史时点可见的因子。
- 默认只接收已经收盘的完整日线；缺交易日、停牌、零成交量不能自行填成成交。复权跳变、代码复用、退市和上市日期均需核验。
- 财务数据按公告可用时间入库；禁止按报告期末日期提前使用。历史成分股及风险标签也须具有时点版本。

## 算法与验证
- 信号只读截至 t 收盘的数据；波段极值日与确认日分别保存，确认前不得引用。禁用居中窗口、负向 shift、全样本拟合和回填历史信号。
- 每个重要因果算法必须有前缀不变性测试：追加未来数据不会改变此前已输出的信号/已确认结构。参数在训练期选定，测试期冻结。
- 变更算法必须同步策略文档、参数、测试和研究日志。必须覆盖负样本、边界、无信号、未成熟标签和损失交易。
- 提交前运行 `python -m unittest discover -s tests -v`、`python -m compileall -q src tests data/scripts`；运行 CLI 帮助/验证。Python 3.11/3.12，核心使用标准库。
- 回测必须同时报告 3/5/10/20 个交易日、全部事件及失败样本、费用假设、MFE/MAE、未成交/删失数量。缺少严格时点数据或交易约束时，只能输出明确标注的研究标签，不能称为可交易收益。
- 不为改善数字删除失败案例。不按未来收益筛选信号。保留实验失败、参数搜索次数和作废原因。
- 不做真实下单。任何订单执行、账户接入和资金操作需另行明确授权。

## Git 协作
- 每次任务用独立分支和小提交，优先 PR 审阅。用户已要求保存研究成果至 GitHub，可推送本项目研究分支；不直接覆盖默认分支，不自动合并。
- 报告注明“真实行情/合成测试”“探索/样本外”“事件研究/可交易组合回测”。没有证据时写“未验证”。
- 若数据或网络受阻，保存可复现错误、缺口和下一条可执行命令，继续完成不依赖外部服务的工作。

## R1 实验
- 新增算法仅在 `src/ashare_quant/r1/`，保留 R0 源码、参数和历史报告。先读 `docs/r1/README.md`、`research/r1/preregister.json` 和最新 `reports/r1/` 报告。
- 独立面板 2024–2026 是封存测试；未经后续明确解封任务，不计算收益标签/分数。指定案例的 2026 结构诊断不能冒充独立验证。不可因验证负结果就解封或继续调参。
- 新结构参数/模型比较另登记实验次数，不覆盖 R1-S1 或隐藏失败。人工评审未输入时保留 pending，不模拟真人标注。
- 含价格图、完整价格区间、解盲钥匙和原始行情仍放 `reports/local/` / `data/` 忽略目录；Git 仅发布白名单派生数据与哈希。盲评包排除解盲钥匙，区域 ID 使用掩码。
- 测试包括中枢/特征前缀不变性、终止状态冻结、图的 as-of 截止检查、训练期预处理和封存边界。研究模型测试依赖可选 numpy，独立 r1-research CI 必须执行，不以核心作业的 optional skip 当成全部通过。
