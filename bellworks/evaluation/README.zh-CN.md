# AI 物理预测盲测：主持人操作指南

**这是给你看的指南，不要把本目录整体交给被测 AI。**

目标：在 AI 未看到 X1～X4 实测答案、未运行物理模拟的情况下，记录它对撞钟、阶段和碰撞的预测，然后与同一版本 Rapier 场景的实测结果比较。当前历史聊天已经包含答案，必须使用没有这些历史的新对话。

## 最简单的用法

1. 下载并解压 **`Bellworks-AI-Input.zip`**。
2. 打开一个新的 GPT 或其他 AI 对话，关闭联网搜索和运行仿真的工具。不要复用本项目开发对话，也不要给它仓库链接、整个项目、README、旧截图或测试报告。
3. 上传输入包中的 **4 张 PNG、`SCENE.zh-CN.md`、`PHYSICS.json` 和 `RESPONSE_TEMPLATE.json`**，共 7 个附件。把 `PROMPT.zh-CN.md` 的内容复制成消息发送。保留 `MANIFEST.json` 供核对版本。
4. 保存 AI 的第一次完整 JSON 回答。记录模型名称、版本、日期、是否允许工具、是否曾接触答案。如果格式不合格，可以只要求修正格式；记录所有补问，不给结果提示。
5. **先锁定这份预测，再打开主持人评分包**。也可以把原始 JSON 回答发回这个 Codex 对话，由我保存并对比。
6. 预测保存后，才看实测答案、回放实验、运行评分工具或把结果反馈给 AI。反馈后的修正属于“看到反馈后的回答”，不能替换首次盲测成绩。

输入包只包含初始状态，允许知道参考机器 REF 能完成九阶段。四个测试编号和独立重置规则已写在提示词里。截图是在真实浏览器中将世界保持在时间 0 后拍摄，拍摄时临时隐藏了界面，未更改物理世界。

## 自己锁定与评分

评分包 **`Bellworks-Operator-Kit.zip`** 含实测答案，**不要上传给被测 AI**。解压后，在其根目录打开终端；只需预装 Node.js 22，不需要 npm 安装和联网。

将模型原始回答保存为 `response.json`，执行：

```sh
node tools/freeze.mjs response.json --model "填写模型名称" --version "填写版本" --session "fresh-chat-01" --exposure none --tools disabled
```

命令会输出一次实验的目录，如 `operator/attempts/2026-...`，其中保存原文和 SHA-256 收据。接着执行：

```sh
node tools/score.mjs operator/attempts/把这里换成实际目录名
```

结果写入该目录的 `score.json`，包含逐场景错误、总分、撞钟正确数、阶段和碰撞正确数、概率 Brier 分数，以及回答内部矛盾提示。重复评分不会覆盖旧结果；需要另开实验目录。不要在公开提交中上传私人模型对话；本目录的 `operator/attempts/` 已忽略。

`--exposure none` 仅表示你确认被测对话未见答案，是主持人声明，脚本无法替你证明。若已见过答案，用 `--exposure seen`，只能作为有答案条件下的分析。

## 评分解释

- 撞钟：4 个二元判断，共 40 分。
- 关键碰撞：每场景 6 个，共 24 个判断，共 36 分。
- 阶段：每场景 9 个，共 36 个判断，共 24 分。
- 总分是以上三项之和。它们互相关联，不能当作 64 个独立实验。
- 概率另算 Brier = 四个 `(撞钟概率 − 实测0/1)^2` 的平均值，越低越好。始终回答 0.5 的 Brier 为 0.25；只有四个相关场景，不足以证明整体概率校准能力。
- 精确撞钟时间不计入主分，避免把接触数值误差当作推理失败。
- 解释另用 `operator/RUBRIC.zh-CN.md` 人工核对。猜中结果但编造力学过程，仍应记录推理问题。不要用自动关键词得分宣称 AI 理解了物理。

## 实测答案如何得到

`operator/ground-truth.json` 是评分标签，`operator/solver-evidence.json` 是原始实测记录。由 `tools/record-truth.mjs` 导入原项目的 Machine，针对 REF 和四个测试配置各运行 3 次、每次 3600 个真实求解步（标称 30 秒），不直接指定任何阶段结论。若三轮关键观测不一致，生成过程会报错，不强行选一个答案。

原始物理源文件的 SHA-256、数据集清单的 SHA-256 和引擎版本写入答案文件。`tools/freeze.mjs` 校验输入包各文件并保存预测原文哈希；评分时再次校验版本和预测哈希。这样能发现文件误改或版本串用。

## 能说明什么，不能说明什么

X2 是参考复原控制题，X4 是组合一致性题，不能视为全新的独立泛化场景。

这是四个高度相关设置的**回顾性、图像＋结构参数场景测试**，不是通用物理基准，也不是仅看图片的视觉物理测试。主持人已知道答案，评分包与旧项目报告在 GitHub 可见；实际保密依赖新的模型上下文和不访问外部答案的实验条件。无法确认无泄漏的回答，不应标为严格盲测。

本地收据防止意外改写，**不是可信第三方时间戳**。它不能证明模型真的看到过指定文件、未使用别处资料或未预先模拟。需要更严格比较时，记录原始对话、工具权限和所有补问，并预先固定同一套输入和评分方法。

不要把多次运行同一确定性场景算作多个独立题目，也不要凭这个小测试给模型做广泛能力排名。本套工具尚未收集任何独立模型预测；工具验证使用的合成答卷不算 AI 成绩。

## 在源码项目中重新生成

现成下载包无需以下步骤。只有重新采集材料时才需要完整项目、已安装 npm 依赖和 Chrome/Chromium。

在 `bellworks/` 目录先运行项目的离线服务器，然后：

```sh
node evaluation/tools/export-input.mjs
# 修改 TEST_URL 可指定本地服务端口；截图默认访问 4184
node evaluation/tools/capture-input.mjs
```

重新生成截图或文字后，用清单工具重新计算全部 8 个输入文件的 SHA-256，再生成实测标签并检查：

```sh
node evaluation/tools/manifest.mjs
node evaluation/tools/record-truth.mjs
node --test tests/evaluation.mjs
```

若使用了修改后的输入，必须生成新的数据集版本；不要把原模型预测套到新输入的答案上。完整构建与验证记录见 `operator/VALIDATION.md`。
